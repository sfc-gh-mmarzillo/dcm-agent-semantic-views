2One repo, one source of truth

The same definitions deploy to both environments. Jinja ({{env_suffix}}) swaps names per target, and the manifest binds each target to its own DCM project.

dcm/manifest.yml 
targets:
  DEV:
    project_name: AGENT_SV_DEMO_DEV
    project_owner: DCM_DEPLOYER
    templating_config: DEV
  PROD:
    project_name: AGENT_SV_DEMO_PROD
templating:
  configurations:
    DEV:  { env_suffix: '_DEV' }
    PROD: { env_suffix: '' }
assets:
  sales_agent_dev:
    path: agents/sales_agent_dev.yaml

4Evals: the release gate

Eval questions and ground-truth rubrics live in the repo, so changing the eval set is itself a reviewed PR. CI snapshots them into a dataset, runs the deployed DEV agent, and fails the check if either metric averages below 0.75.

What the gate catches

Agent regression

The instructions get edited to "never use tools", answer correctness collapses, and the PR is blocked.

Semantic layer break

A metric is renamed or its formula changes, the numbers drift from the ground truth, and the PR is blocked.

Scope creep / hallucination

The agent answers the weather question instead of declining, the boundary test fails, and the PR is blocked.

5Production-minded details

Least-privilege deploys

  • Dedicated role DCM_DEPLOYER owns both projects. CI never uses ACCOUNTADMIN.
  • CI authenticates as CI_DCM_USER (TYPE = SERVICE) with key-pair auth. The private key lives only in GitHub secrets.
  • Each deploy gets an alias (pr-<n>-<sha>, main-<sha>), giving a traceable history.
  • The shared DEV environment is serialized with GitHub concurrency.
Preview status (per the DCM SV / Agents PuPr doc)
  • DEFINE AGENT is Private Preview and not yet enabled here. A fallback in post_deploy.sql handles it until then.
  • Project assets aren't Jinja-rendered, so there's one agent spec per environment.
  • Semantic views from YAML assets are only proposed, so the semantic view is defined inline in SQL.
  • Demo seed data is reloaded on every deploy. Remove the seed inserts before pointing this at real tables.
